<task type="auto">
  <name>Task 1: Sentence model</name>
  <action>Split on [.?!] and newlines, not on ":". Classify every sentence with \b regexes, in this order: timeline, content/assets, feature, design, page, goal. A sentence is conditional when it contains \b(maybe|might|perhaps|possibly|if|ideally|optional|nice to have)\b. Evidence is the sentence, capped at 25 words.</action>
</task>
<task type="auto">
  <name>Task 2: Deliverables, each with its own label</name>
  <action>Pages: one deliverable per known page name found (Home, About, Services, Products, Contact, Blog, FAQ, Pricing, Portfolio, Gallery, Shop, Team, Careers). Unknown items that follow "maybe" in a page list go to Pending. Design: "Mobile-friendly layout", "Visual style inspired by X", "Homepage look and feel", "Visual design direction". Content: "Client-supplied assets". Features: "<Name> integration" or a capitalised keyword. Conditional features go to Pending plus an ambiguity (Rule 3). Labels are de-duplicated before output, so V6 never fires.</action>
</task>
<task type="auto">
  <name>Task 3: Summary, title, ambiguities, questions, risks and clarity from the data</name>
  <action>Goal: "Build a new website for the client, targeting <wording>." Paragraph: 3–4 sentences listing the pages, style, assets, conditional items and timeline. Title: hint, else "<Noun> project". Ambiguities: deadline (UNCLEAR with wording, else MISSING); each conditional item; design references (UNCLEAR "like X", else MISSING); assets (UNCLEAR when "still working on / not ready", MISSING only when no asset words appear); business context (MISSING unless described); budget/approval (LOW, standard). Write one question per ambiguity. Risks: timeline (HIGH when the window starts within 21 days), assets, scope creep, integration and design subjectivity, padded to at least 4 with generic risks. Clarity scores follow the rubric (full / half / zero).</action>
</task>
